# Body-locked tracking and movement games

Approved in chat on 2026-10-29: improve camera and skeleton tracking first, then add curl bubbles, pushup levels and cardio reach. One phone/laptop camera; on-device inference. Existing worktree changes must be preserved.

Camera: use one image coordinate system across video, 2D and depth overlays, including portrait letterboxing and mirroring. Display smoothing must prioritize registration; analysis smoothing remains independent. Reject invalid or implausible landmark jumps without inventing observations; recover after fresh consistent evidence. Expose rejected joints and actual provider/model/delegate/latency. Provide Full/Lite/Heavy MediaPipe plus a functional non-MediaPipe body-keypoint backend for comparison. Never fabricate missing joints or metric depth. Select defaults conservatively; a heavier model is not a demonstrated accuracy win.

Games: use body-relative calibrated targets, observable movement and interruption-safe cycles. Curl bubbles require a target visit and controlled return. Pushup levels require complete verified reps; progression increases required consistency, not forced depth. Cardio reach alternates hand targets with return-to-home between hits. No score for stationary holds, jitter, hidden joints, low cadence, stale frames or cycles crossing interruptions. Targets have visible space inside the camera image. Rest, restart, exit and difficulty controls work; games are separate from persisted workout coaching scores.

Validation: deterministic camera alignment, artifact adapters, jump/recovery, smoothing cadence/scale and game replay tests. Browser tests click all new controls at desktop and phone sizes. Actual inference smoke tests establish model load and execution only. No claim of human accuracy without representative labeled recordings. Re-check the entire user design law, emphasizing visible content, useful live overlays, contrast, edge clearance and functioning controls.
